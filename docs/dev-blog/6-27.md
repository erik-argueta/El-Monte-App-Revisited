## Goal
Implement a persistent Bottom Navigation Bar so users can quickly access `Home`, `Calendar`, and `Profile`

## Results
I asked Claude.ai if there was a way to make a navigation bar persistent throughout the application. It provided code for using ShellRoute and a new widget that would be displayed on the navigation bar.  

### What is ShellRoute?
A route that displays a UI shell around the matching child route.  
This tool extends and allows the use of different children with the navigation bar as long as it is provided with a `parentNavigationKey`.  

ShellRoute was implemented in the `app_router.dart` file, and routes were moved from the already written GoRoutes.  

## main_shell.dart Breakdown
Claude.ai generated a template for the widget, and I augmented it to fit my application's needs. The following segment is going an in-depth breakdown with some AI assistance in understanding and explaiing.

### GoRouterState.of(context).uri.toString() breakdown
Whenever `MainShell` must rebuild (which happens at every route change since `child` changes), the following line runs:  
`final String location = GoRouterState.of(context).uri.toString()`

`GoRouterState.of(context)` fetches the routing info associated with the current build context.  
`.uri` pulls the current location as a URI object  
`toString()` converts the URI object into a plain string  

### _indexForLocation breakdown
this turns the path into a tab index. This takes that `location` string in the argument and highlights the corresponding nav bar icon by returning an index.  
* 0 -> Home tab 
* 1 -> Calendar tab 
* 2 -> Profile tab

NOTE: `location.startsWith(...)` allows for the nav bar icon to be highlighted in nested pages within `/calendar` and `/profile`

### _onTap breakdown
This handles the reverse direction so when the user taps a tab it directs them to the appropriate page. `BottomNavigationBar` automatically tells you which icon index the user tapped via its `onTap` callback:  
`onTap: (index) => _onTap(index, context)`  


---
## Conclusion
When the user taps on an icon, Flutter hands the index number. The `switch` block then converts the index back into a navigation call: `context.go('/...')`. This then tells `go_router` to change the URL/route, which then causes `child` in `MainShell` to update the desired page.  

Claude Summary:  
How they connect as a loop

1. User taps "Calendar" icon → onTap fires with index = 1
2. _onTap(1, context) runs → context.go('/calendar')
3. go_router updates the route → MainShell rebuilds with child = CalendarPage()
4. On rebuild, location is recalculated → now equals "/calendar"
5. _indexForLocation("/calendar") returns 1
6. currentIndex: 1 → Calendar icon now shows as highlighted/selected

So `_onTap` handles tap → navigate, and `_indexForLocation` (combined with reading `location`) handles navigate → highlight. They're mirror images of each other, keeping the nav bar's visual state and the actual route always in sync — even if navigation happens some other way (e.g., a button on Home calling `context.go('/calendar')` directly, bypassing the nav bar entirely — the highlight still updates correctly because it's derived from the actual current route, not from manually tracked tap state).
