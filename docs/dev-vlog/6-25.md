## Goal
Begin implementing routing within the application.  

## Results 
Learned more about Flutter's navigation packages: `Router`, `Navigator`, and `go_router`.  
I wanted to ensure I was picking the proper navigational packages before I actually built anything; I was worried that I may have to go back and augment my code to fit the navigating package that best suited my application's needs.  
My concern was the verbage on the official Flutter Documentation: [https://docs.flutter.dev/ui/navigation].  

In my mind, I was visualizing the Site Map and considered the nature of the application. The application is to act as a medium for users to make the official website's resources more accessible; with this in mind, Named Routes seemed like the better choice. However, the documentation highlights a note that discourages the use of named routes for most applications and instead recommended using `go_router`.  

Additoinally, this was on the page:  
"Flutter provides a complete system for navigating between screens and handling deep links. Small applications without complex deep linking can use Navigator, while apps with specific deep linking and navigation requirements should also use the Router to correctly handle deep links on Android and iOS, and to stay in sync with the address bar when the app is running on the web."

I asked ChatGPT to explain what the section meant as I did not know what Deep Links were. Ultimately, GPT explained Deep Links as a link that opens a particular page in your application. Its use being if someone were to click the link elsewhere on their phone, the app opens and directs the user to that page from within the app.  
Being as how the application is aimed to improve accessibility, I decided deep links were unnecessary for the scope of my project. The only area I would need to utilize Deep Links, however, with official public announcements from the city.  
I am planning to implement Push Notifications whenever an official announcement is made, so I am anticipating to use Deep Links there; therefore, it was best to use `go_router` for the entirety of the project.
